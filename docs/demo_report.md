# 0.8.0 시연·실시간 신경회로 시험 — 2026-09-26

## 최종 동적 시험

60m×10m Webots 복도, 출발 x=-26m, 전진 명령 유지, 박스 3종·횡단 보행자 2명·3m 통로(벽체 2개), 60초 시뮬레이션이다. 통과 수 7개는 보행자 2명·박스 3개·통로 벽체 2개의 x방향 통과를 관찰자가 계산한 값이며 제어기의 경로 입력으로 사용하지 않는다.

|---|---:|---:|---:|---:|---:|---|
| mock / 기본 2m/s | 54.693m | 7 | 1 | 0 | 0 / 0 | 통과 |

각 시험은 1,874회 뇌 step을 수행했다. **각 보행자 최소 이동 거리 29.952m**로 실제 이동을 확인했다. 완료 검사는 충돌·뇌/관제 오류 0, 50m 이상 이동, 장애물 7개 통과, 사용자 진행 방향 복귀 1회 이상, 각 보행자 5m 이상 이동을 모두 요구한다. 기본 2m/s는 시속 7.2km다. 모터 상한과 사용자 요청값이 실제 전체 구간 평균 속도를 뜻하지 않는다.

mock 최소 거리 추정 0m, 실제 GPU 0.028m는 외접 형상 기반 보수적 참고값이다. 접촉 여부는 Webots 접촉점으로 별도 검사하며 이 추정값은 제동 여유 보증이 아니다. 전 구간 통과 뒤에도 전진을 계속 요청하면 끝벽 근처에서 회피/정지한다. 모든 자유 조종 상황에서 무충돌을 보장하는 결과가 아니다.

재현: `scripts/check_pipeline.sh corridor_demo 60 forward` (mock), `REFLEXGUARD_BRAIN_PROFILE=real scripts/run_webots.sh` (실제 GPU·관제 대화형). 자동 실제 주행은 `env REFLEXGUARD_BRAIN_PROFILE=real scripts/run_scenario.sh corridor_demo 60 forward`; 관제 연동 시험에서는 `.env.control`도 환경으로 주입한다. 배치 결과 JSON은 `python -m reflexguard.simulation.verify`로 완료 조건을 검사한다. `run_scenario.sh` 자체의 종료 성공만으로 회피 성공을 판정하지 않는다.

## 실패와 수정 이력

- **이전 정적 조건 정정:** 초기 보행자 두 명의 이름이 같아 이동 컨트롤러가 종료됐다. 당시 mock 54.768m/실제 54.946m·7개 통과 결과는 보행자 정지 조건이다. `demo-mock-2mps.*`, `demo-real-2mps.*`, `demo-mock-3mps-blocked.*`는 최종 동적 시험으로 인용하지 않는다. 이후 고유 이름과 보행자 이동 거리 완료 검사를 추가했다.
- 보행자가 움직이자 t=21.440초 첫 보행자와 1회 접촉했다. 상체 높이 센서만 추가해서는 해결되지 않았다. 4방향·두 높이 센서, 자체 이동을 제거한 물체 군집 추적, 3초 미래 위치 예측과 불확실성 여유를 적용했다. 어느 높이든 오류이면 정지한다.
- 2m 통로 후보는 충돌 없이 정체되어 43.022m·4개 통과에 그쳤다. 최종 통로는 3m다. 초기 박스 B/C 간격 3m도 정체되어 8m로 조정했다.
- 3m/s 무제한 접근 후보는 동적 보행자와 t=23.008초 접촉 1회가 발생했다(`demo-dynamic-mock-3mps.*`). 고속 요청은 유지하되 장애물·측벽이 6m 안이면 2m/s 이하로 감속하도록 수정했다. 따라서 현재 10m 폭 복도에서 3m/s 요청은 대부분 2m/s 이하로 실행된다.
- 최적화 전 실제 GPU는 533 step 뒤, CUDA Graph 적용 후 전체 뉴런을 매 step 전송하던 시험은 369 step 뒤 응답 시간 초과로 정지했다. 전체 뉴런 전송은 약 500ms마다로 줄이고 위험 출력은 매 step 유지했다.
- 최종 동적 시험의 첫 실제 GPU+관제 실행은 1,459 step 뒤 200ms 만료로 정지했다. 충돌 0·54.465m·7개 통과였어도 통신 오류가 있어 실패다(`demo-dynamic-live-timeout.*`). 관제 없는 다음 실행도 135 step 뒤 만료했다(`demo-dynamic-real-timeout.*`). 이후 위 표의 실제 GPU+관제 실행은 전체 통과했다.

서버 150ms·클라이언트 200ms 제한, 실패 후 정지 고정 정책을 완화하거나 성공할 때까지 자동 재시도하지 않았다. CUDA Graph는 계산 지연을 줄이지만 VPN·공유 GPU·VM의 장기 지연을 보장하지 않는다. 통신 실패를 없앴다고 주장하지 않는다.
