# 뇌 서버 성능과 수치 검증 — 0.8.0

2026-09-25 Jetson Thor, NVIDIA PyTorch 25.08, CUDA 13.0, NumPy 1.26.4. 기존 vLLM 서비스와 GPU를 공유했으며 다른 컨테이너를 중지하거나 드라이버를 바꾸지 않았다. 187뉴런·185간선의 축소 LIF 회로다.

| 시험 | 횟수 / step | 중앙값 | p95 | 최대 |
|---|---|---:|---:|---:|
| GPU 내부 계산+응답 생성 | 120 / dt_ms=50 | 18.59ms | 86.54ms | 91.25ms |
| 개발 VM→VPN→SSH→mTLS API 왕복 (최종 이미지) | 100 / dt_ms=50 | 40.65ms | 44.40ms | 54.29ms |

별도 시각에 측정한 표이므로 GPU 계산 p95와 왕복 p95를 서로 빼거나 더하지 않는다. CUDA 동기화를 포함하고, 준비 실행은 제외했다. 왕복 측정은 지속 연결의 HTTP 요청부터 Pydantic 응답 검증까지다. 초기 TLS 연결 비용과 장기 부하 안정성의 상한을 뜻하지 않는다.

`scripts/check_brain_perf.py`에서 정지 입력, 약한/강한 좌·우 입력, 양측 입력, 출력 침묵을 번갈아 120회 적용했다. CUDA와 NumPy의 발화율/API 출력은 동일했고 막전위는 atol/rtol 1e-5로 일치했다. 증거: `logs/brain-gpu-perf.json`, `logs/phase7-real.json`.

서버는 최대 16세션, TTL 900초, 대기/실행 합계 4요청, 단일 GPU worker, 대기 20ms, 요청 전체 시뮬레이션 150ms를 제한한다. 5ms 시뮬레이션 간격마다 실제 경과 시간을 검사한다. CUDA 드라이버가 멈추는 경우 강제 선점하는 하드 실시간 watchdog은 아니다. 만료/취소/불확실한 상태에서는 서비스 전체를 실패 상태로 두고 재시작이 필요하다. 부분 계산은 세션에 반영하지 않는다.

클라이언트 전체 응답 제한 200ms는 유지했다. 보정 중 정면 시험 한 번에서 200ms 만료가 발생하여 감속 정지가 고정됐다(`logs/phase6-basic-timeout.log`). 이후 전체 통합 시험에서는 뇌/관제 오류가 0회였다. 단일 성공 리허설이 VPN·공유 GPU의 장기 지연을 보장하지 않는다. 실제 제어 장비에는 독립 제동 watchdog과 비동기 제어 주기 검증이 필요하다.


## 0.8.0 CUDA Graph 및 발화율 전송

32/50ms 반복은 서비스 준비 단계에서 CUDA Graph로 캡처하고 단일 worker에서 재생한다. 그 외 1..100ms는 기존 반복 계산을 쓴다. replay 입력·출력은 worker 전용 버퍼이며 반환 세션 상태는 복제해 다른 요청이 변경하지 못한다. 150ms 서버/200ms 클라이언트 제한은 유지한다. 그래프 전후 경과 시간을 검사하므로 그래프 내부 5ms 간격 검사는 없으며, 하드 실시간 선점 보장은 아니다.

공식 근거: [PyTorch 2.8 CUDA Graph 문서](https://docs.pytorch.org/docs/2.8/notes/cuda.html#cuda-graphs). 고정 버퍼·준비 실행·캡처·새 입력 복사·재생 방식을 사용한다.

- 50ms 120회 계산: 중앙값 7.517ms, p95 10.140ms, 최대 11.163ms. 이전 표와 측정 시각/부하는 달라 엄밀한 동일 부하 비교는 아니다.
- 32/50/7ms 교대 120회: 중앙값 5.847ms, p95 9.028ms, 최대 77.022ms. CPU/CUDA 전체 발화율과 상태 일치, 세션 격리, 만료 요청 거부 확인.
- 실제 mTLS 50ms 100회 왕복: 중앙값 28.274ms, p95 40.246ms, 최대 50.656ms. 클라이언트 인증서/토큰 누락 거부와 출력 침묵 계약 통과.
- 이 짧은 측정과 달리 Webots 장시간 시험에서는 200ms 만료가 반복 관측됐다. 계산 최적화만으로 VPN·VM 부하의 지연을 해결했다고 주장하지 않는다. 실패 기록은 demo_report.md.

전체 뉴런 배열의 전송은 최종 버전에서 시뮬레이션 약 500ms마다로 제한하고 위험 출력은 매 step 유지했다. 이후 보행자 정지 조건의 실제 GPU 60초 시험은 1,874개 step·7개 장애물 통과·뇌 실패 0회였다. 보행자 이동 오류를 수정한 최종 동적 시험은 demo_report.md에 별도로 기록한다. 실패 전후 기록은 모두 보존했다.

최종 동적 트랙·관제·Firefox 동시 실행은 60초 시뮬레이션에서 뇌 step 1,874회·7개 장애물 통과·뇌/관제 오류 0회로 통과했다. 동일 조건의 앞선 실행에는 1,459 step 뒤 시간 초과가 있었으므로 이는 단일 성공 실행의 결과다.
