# 뇌 서버 성능과 수치 검증 — 0.7.0

2026-09-25 Jetson Thor, NVIDIA PyTorch 25.08, CUDA 13.0, NumPy 1.26.4. 기존 vLLM 서비스와 GPU를 공유했으며 다른 컨테이너를 중지하거나 드라이버를 바꾸지 않았다. 187뉴런·185간선의 축소 LIF 회로다.

| 시험 | 횟수 / step | 중앙값 | p95 | 최대 |
|---|---|---:|---:|---:|
| GPU 내부 계산+응답 생성 | 120 / dt_ms=50 | 18.59ms | 86.54ms | 91.25ms |
| 개발 VM→VPN→SSH→mTLS API 왕복 (최종 이미지) | 100 / dt_ms=50 | 40.65ms | 44.40ms | 54.29ms |

별도 시각에 측정한 표이므로 GPU 계산 p95와 왕복 p95를 서로 빼거나 더하지 않는다. CUDA 동기화를 포함하고, 준비 실행은 제외했다. 왕복 측정은 지속 연결의 HTTP 요청부터 Pydantic 응답 검증까지다. 초기 TLS 연결 비용과 장기 부하 안정성의 상한을 뜻하지 않는다.

`scripts/check_brain_perf.py`에서 정지 입력, 약한/강한 좌·우 입력, 양측 입력, 출력 침묵을 번갈아 120회 적용했다. CUDA와 NumPy의 발화율/API 출력은 동일했고 막전위는 atol/rtol 1e-5로 일치했다. 증거: `logs/brain-gpu-perf.json`, `logs/phase7-real.json`.

서버는 최대 16세션, TTL 900초, 대기/실행 합계 4요청, 단일 GPU worker, 대기 20ms, 요청 전체 시뮬레이션 150ms를 제한한다. 5ms 시뮬레이션 간격마다 실제 경과 시간을 검사한다. CUDA 드라이버가 멈추는 경우 강제 선점하는 하드 실시간 watchdog은 아니다. 만료/취소/불확실한 상태에서는 서비스 전체를 실패 상태로 두고 재시작이 필요하다. 부분 계산은 세션에 반영하지 않는다.

클라이언트 전체 응답 제한 200ms는 유지했다. 보정 중 정면 시험 한 번에서 200ms 만료가 발생하여 감속 정지가 고정됐다(`logs/phase6-basic-timeout.log`). 이후 전체 통합 시험에서는 뇌/관제 오류가 0회였다. 단일 성공 리허설이 VPN·공유 GPU의 장기 지연을 보장하지 않는다. 실제 제어 장비에는 독립 제동 watchdog과 비동기 제어 주기 검증이 필요하다.
